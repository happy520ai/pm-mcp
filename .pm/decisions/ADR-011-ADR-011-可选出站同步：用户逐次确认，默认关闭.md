# ADR-011 ADR-011 可选出站同步：用户逐次确认，默认关闭

- 日期: 2026-11-05
- 状态: 已接受

## 背景

用户希望被 pm 纳管的项目在本地更新后能同步到云端（GitHub/Gitea 等 git 服务，或自建服务器）。这与 ADR-002（全部离线）、ADR-008（不 push 远端）及 AGENTS.md 红线（禁止 git push）冲突。用户明确约束：1) GitHub/Gitea 与自建服务器都支持，但均为用户可开启/关闭的选项；2) 每一次同步都必须由用户确认具体同步哪些内容，不得盲目推送，防止代码泄露。

## 决定

新增“可选出站同步”能力，仅在同步子系统范围内替代 ADR-002/ADR-008 中与之冲突的部分：(a) 默认关闭，按项目在 .pm/sync.json 显式开启，并提供全局一键关闭；(b) “实时”只指实时检测变更并生成待确认清单（manifest：文件路径、内容哈希、体积、密钥扫描结果、目标远端与 ref），不等于实时推送；(c) 推送必须绑定用户对该 manifest 的批准，批准携带 manifest 哈希，清单之后任何文件变化都使批准失效；(d) 批准只能经带外渠道（终端 CLI `pm-mcp sync approve` 或本地 UI）由人完成，MCP 工具和 AI 代理只能生成清单、查看状态，不能自行批准或推送；(e) 推送前强制过密钥扫描与 .gitignore/scan-policy，命中高危直接阻断，批准也不能覆盖；(f) 用 git plumbing 生成快照提交，推到专用 ref（refs/pm-sync/<机器名>），不触碰工作区、暂存区和用户分支；(g) 凭据只走系统 git credential helper 或 SSH key，不写入 .pm/ 或共享目录；(h) 每次同步（含拒绝、阻断）写入审计日志。ADR-002 与 ADR-008 的其余内容（工具默认不联网、编排不 push）保持有效。

## 后果

代价：不是无人值守的全自动同步，用户每次需确认，吞吐低于全自动；换来出站内容可审计、可控，泄露面最小。放弃的方案：watcher 触发后自动推送（有泄露风险）、自建文件同步协议（重复造轮子）。后续：sync-daemon 只负责检测与排队待批清单、对已批准清单执行推送，不会自行扩大范围；服务端聚合看板属后期阶段，需另立 ADR。
