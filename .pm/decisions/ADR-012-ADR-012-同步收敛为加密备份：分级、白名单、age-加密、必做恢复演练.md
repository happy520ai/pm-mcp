# ADR-012 ADR-012 同步收敛为加密备份：分级、白名单、age 加密、必做恢复演练

- 日期: 2026-11-05
- 状态: 已接受

## 背景

ADR-011 确立了可选出站同步、默认关闭、用户逐次带外确认。随后用户澄清：云端只做备份，不需要服务端浏览或看板，且项目中没有绝对不能外发的内容。用户同时要求评估是否存在零风险方式；结论是内容一旦离开本机就无法撤回，风险只能降低不能归零。

## 决定

在 ADR-011 约束全部保留的前提下补充：(a) 项目配置 tier 分级：local（默认，不联网）、private-server、encrypted、hosted；开启远端备份时默认推荐 encrypted，hosted（明文）需额外一次终端确认；(b) 清单采用白名单加黑名单的与关系：必须在 include 内且不在黑名单（.env*、*.pem、*.key、id_rsa*、*.pfx、credentials*、.git/、node_modules/）内；(c) 内容检查含密钥扫描、熵检测、体积上限、二进制文件需逐个确认；(d) encrypted 层级推送前用 age 对快照归档做客户端加密，归档名用哈希，提交作者与邮箱匿名，提交信息只含时间与清单哈希；age 私钥只放离线介质，不进 .pm/ 也不进同步；(e) 推送前用 git ls-remote 等检查仓库可见性，公开仓库阻断（加密模式需单独确认）；remote 地址变化使旧批准全部失效；(f) 提供 pm-mcp sync restore，恢复到指定空目录，并强制做一次备份加恢复哈希比对演练，才算备份能力交付；(g) 取消服务端接收端与跨机聚合看板（原 P3）；(h) 泄露应急顺序：先换密钥，再删远端，因为远端内容可能已被缓存或克隆。

## 后果

代价：私钥丢失即无法恢复，所以恢复演练为硬性验收；远端可见备份时间、次数与密文总体积；服务端无法预览差异。放弃：明文推送为推荐项、服务端看板、watcher 自动推送。ADR-011 全部条款继续有效，本 ADR 只增补，不替代。
