# ADR-008 ADR-008 编排分工定位：控制流外置，pm-mcp 只记账与发指令

- 日期: 2026-10-27
- 状态: 已接受

## 背景

目标：从项目一开始就让模型借助 pm-mcp 自我迭代——拆任务、建卡、多会话并行执行、汇总验收，跑到目标完成。讨论过三条路：① pm-mcp 主动 spawn 外部编码工具（需 API Key、联网、托管长驻进程，且 zcode/qoder 无头入口不统一）；② 自建任务队列 + 租约抢占锁（但 workflow 运行时已负责串行派发与并发，自建锁属重复机制）；③ 控制流外置、pm-mcp 做持久账本。关键约束：pm-mcp 作为 MCP 工具服务无法主动唤起会话；ADR-002 已定「全部离线、不调用模型」；单个 workflow 运行挂在应用进程上，进程退出即 interrupted，没有自动拉起。

## 决定

控制流归外部定时任务与 workflow（它们是唯一天然能「发起」会话的一侧）；pm-mcp 只做三件事：目标锚点（最终目标 + 机器可判定的验收标准）、可手动开关的编排配置（enabled / max_concurrency / 预算上限 / 断点 / 停滞计数）、状态可见性（get_status 自证）。pm-mcp 仍然不联网、不要 Key、不调用任何模型，也不唤起任何会话。执行模型为「短轮次 + 断点续做」：不依赖单个长驻运行，每轮有界，结果与断点写回台账，进程退出后下一轮从断点续。开关存放在 .pm/orchestrator.json，任何会话可读可改；台账缺失或损坏一律视为禁用（fail-closed），防止损坏状态导致整晚空转烧额度。

## 后果

1) ADR-002「全部离线」的适用范围必须收窄为「扫描与检索类功能离线」——编排开关本身不触发任何模型调用，未违反原意，但原文表述会自相矛盾，需在 ADR-008 中显式收窄。2) 代价：需要用户自行创建定时任务并保持机器常开；pm-mcp 无法保证 24 小时连续，只保证「断了能从断点续」。3) 放弃的方案：pm-mcp spawn 编码工具（引入 Key/联网/进程托管三重负担）、任务卡自建租约抢占锁（与 workflow 运行时职责重复）。4) 「直到完成」必须有机器可判的终点与停滞检测，否则验收标准含糊时会长时间空转。
