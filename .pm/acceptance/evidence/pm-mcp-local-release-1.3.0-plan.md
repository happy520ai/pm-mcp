# pm-mcp 本地评价计划（基线 1.3.0）

基线：`pm-mcp-local-release@1.3.0`。本版只做一处门槛同步：把 `QR-FS-TOOLS` 的 `MCP tools` 阈值与配套测试 `AT-FS-TOOLS` 的断言，从 `equal 58` 改为 `equal 59`。

原因是边界可靠性硬化新增了 `complete_goal` 工具（目标完成终止态），直连探针实测工具数为 59。`equal` 断言对“新增工具”天然不可能满足，旧基线会把这次演进判定为失败。

同时更正基线自述里的旧版本号：1.2.0 的标题/产品/范围仍写 `pm-mcp 0.3.0`，与当前 `package.json` 的 0.7.0 不一致；本版将其更正为 0.7.0，并注明边界硬化范围。除工具计数外，没有放宽任何量化阈值、验收要求、风险控制或测试追踪。

不变的部分：其余全部量化阈值（覆盖率、失败/跳过/取消计数、治理覆盖率、安全未处理数等）、评价策略、冻结指针与证据摘要规则均原样保留。本版没有为了让门禁变绿而降低任何质量门槛。

执行顺序：

1. 基线批准后在当前工作区重新采集产品证据，绑定当次源码摘要。
2. 先运行 `npm run quality` 生成与当前源码绑定的质量报告，再执行结构、安全、许可证与治理检查；有硬红旗不推进。
3. 完整执行 test、build、typecheck、coverage；门槛维持 package.json 的 lines 95%、branches 85%、functions 93%，保留全部失败/跳过/缺失结果。
4. 按冻结指针复算证据 SHA-256，生成不可覆盖的机器判定报告。
5. 报告与原批准基线一并入库，1.2.0 保持不变。

范围边界：Windows x64 本地第一方评价，Node.js ≥ 22.18。批准仅用于同步工具目录与硬化后的本地质量基线，不构成远程发布授权、独立认证或托管 CI 证明。历史上已记录的 20 GiB 容量基准仍按其原始日期作为既有资格证据，不冒充本版新增压测。

回滚：1.2.0 基线与其评价证据保持原样未修改；`package.json` 的 `pm_mcp.acceptance_baseline.version` 指回 1.2.0 即回到旧状态。
